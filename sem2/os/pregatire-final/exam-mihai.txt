Answer:
The functionality of the program will remain the same. Mutexes provide mutual exclusions for all threads (doesn't differentiate between writers and readers).

Rwlock makes a differentiation between these 2:
    - wrlock allows just ONE thread to execute, blocking all other wrlocks and rdlocks (only one writer can 'write' at a time)
    - rdlock allows MULTIPLE threads to execute, blocking only the calls to wrlock (no writers allowed).

Since we're working only with calls to wrlock, only one thread will be able to execute at a time, maintaining mutual exclusion.

RO: Care este diferenta dintre politicile de planificare SJF si STCF?
EN: What is the difference between the SJF and STCF scheduling policies?

Answer:
The SJF (Shortest Job First) checks which job is shorter when they arrive, and places them accordingly. This approach works well if all jobs would arrive at the same time, which is unprobable.
Jobs that arrive at different times can cause a situation when the longer job that arrived first is placed before the shorter job, but which arrived later, in execution

The STCF fixes this problem by checking each job's time of completion. When a job that has a lower completion time enters the execution, the scheduler pauses the previous (possibly longer) job (puts it into READY) and lets the shorter job execute. After the job's execution, the other process is unpaused.

RO: Cum difera un link hard de unul simbolic?
EN: What are the differences between a hard link and a symbolic link?

Answer:
A symoblic link links to a FILE PATH. Therefore it can become broken when the path becomes non-existent (the file gets deleted). It does not update the i-node's link count. It can be made cross-partition. IT GETS A NEW I-NUMBER (inode)

A hard link represents a link to the FILE's I-NODE. When it gets made, the i-node's link count gets updated, which causes the file to not get deleted (even if the original path is removed) until after all the references to the inode are removed. It cannot cross partitions. It gets the same I-number (i-node) as the file.
